# Roadmap 3 candidate records

These records pre-plan ideas that may follow or extend Roadmap 2. They are not
accepted specifications, implementation epics, release promises, or Proofbound
claims.

The [candidate register](../product-roadmap-3-candidates.md) owns candidate
priority and promotion. The
[product roadmap execution order](../product-roadmap-execution-order.md) owns
the dependencies between active Roadmap 2 work and candidate promotion. The
[platform integration contract](../specs/0013_platform_integration_contract.md)
owns shared vocabulary, identities, composition, compatibility, and repository
boundaries.

| Candidate | Record | State |
| --- | --- | --- |
| Validation | [Reference workloads](reference-workload-validation.md) | Start discovery now |
| RT-14 | [Credential custody and secret delivery](rt-14-credential-custody.md) | Explore interfaces; implementation blocked |
| RT-15 | [Operation-scoped mediation](rt-15-operation-scoped-mediation.md) | Preserve design space; implementation blocked |
| RT-16 | [Organizational policy lifecycle](rt-16-organizational-policy-lifecycle.md) | Gather adopter evidence |
| RT-17 | [Integration-profile registry](rt-17-integration-profile-registry.md) | Define contents; registry blocked |
| RT-18 | [Multi-language capability analysis](rt-18-multilanguage-capability-analysis.md) | Define adapter boundary |
| RT-19 | [Evidence discovery and export](rt-19-evidence-discovery-and-export.md) | Preserve query/trust separation |
| RT-20 | [Host and fleet identity](rt-20-host-fleet-identity.md) | Research questions only |

Every candidate record includes a start gate, a rejection gate, and an owner.
Implementation starts only after the candidate register records promotion.
